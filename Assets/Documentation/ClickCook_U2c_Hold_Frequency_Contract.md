# U2c — частота утримання

ADOPTED IMPLEMENTATION CONTRACT — 2026-10-24. Перший вузол сімейства з node manifest; числа є початковим балансом ClickCook, а не source rewards чи результатом pacing playtest.

- `node.hold_frequency.01` / «Робочий ритм I»: 10 окремо придбаних рангів, prerequisite `node.click_hold.01:1`. Ціна наступного рангу N: `ceil(300 × 1.6^N)` у decimal, округлення наприкінці. Перші ціни 300/480/768; десята — 20616; загальна ціна — 54479 у.е.
- Відкритий Hold має базові 4 рухи/с. Цей вузол додає 0.5 руху/с за придбаний ранг: `f = 4 + 0.5N`, 4.5 після першої покупки, 9 при N=10. Інтервал повтору — `1/f` секунди unscaled time. При закритому Hold ефективна частота 0; частота сама його не відкриває.
- Частота впливає тільки на повтори Hold. Початковий удар негайний, Enter — один удар, release не атакує. Розмір удару/крит і нагорода лишаються в чинному manual pipeline. Не більше одного повтору за кадр; після затриманого кадру наступний дедлайн рахується від поточного часу, без боргу/пакета ударів. Пауза, focus, Back, result, end, disable й зміна order скасовують Hold за контрактом U2b.
- Купівля лише між днями через чинні node quotes, дебет/автозбереження й повторну перевірку рангу/передумов. Дерево показує current→next, ціну/межу 10, статистика і підказка прилавка — фактичну частоту.
- Schema 4 додає цей canonical nodeId з рангом 0–10. Schema 1/2/3 зберігають свої whitelist; частота в них недійсна. Load старих профілів не переписує файл і не дарує ранги; наступний звичайний Save пише 4, зберігаючи wallet/XP/попередні ранги. Старі backups читаються, version >4 захищена. Активний жест/дедлайн не зберігаються.
- `node.hold_frequency.02` / «Ритм шефа II» зберігає prerequisite першого вузла `:max`, але ще не продається, не зберігається й не має числового preview. Його cap/ціна/внесок визначатимуться окремо.

Локальні ризики для перевірки: неправильний інтервал/накопичення повторів, зайвий дебет чи обхід cap/передумов, втрата старих ranks/XP/wallet при schema boundary, застарілий UI темпу. Потрібні model/storage checks та один ізольований live purchase→Hold→Continue pass. Player build і широка регресія не потрібні.
