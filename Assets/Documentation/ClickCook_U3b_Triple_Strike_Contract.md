# U3b — другий ступінь шансу та потрійний рух

ADOPTED IMPLEMENTATION CONTRACT — 2026-10-24. Node IDs/передумови з manifest; числа — початковий баланс ClickCook, не source rewards чи результат pacing playtest.

- `node.double_strike_chance.02` / «Другий рух II»: власні 5 рангів після всіх 10 рангів `.01`. Внесок +2 п.п./ранг, додається до першого вузла: `d = .02 × (N1 + N2)`, максимум 30%. Ціна `ceil(50000 × 1.6^N2)`; 50000/80000/128000/204800/327680. Перший вузол зберігає власні ціну/10 рангів/20%.
- `node.triple_strike_chance.01` / «Потрійний рух I»: власні 10 рангів після `.02:1`, +1 п.п./ранг, `t = .01N3`, максимум 10%. Ціна `ceil(10000 × 1.8^N3)`, decimal з одним кінцевим округленням вгору. N — придбаний ранг конкретного вузла.
- Один прийнятий manual/Enter/Hold trigger: первинний удар, потім, лише якщо HP > 0 та d+t > 0, **один** uniform proc-roll u∈[0,1). `u < d` → один повтор (2 удари загалом); `d ≤ u < d+t` → два повтори (3 загалом); `u ≥ d+t` → без повтору. Ймовірності взаємовиключні: P(2)=d, P(3)=t, P(1)=1−d−t. Triple додає окрему ймовірність і не відбирає шанс double. При t=0 попередній U3 розподіл незмінний. Поточні caps дають d+t≤.40, додаткова нормалізація не потрібна. Пороги рахуються з цілих процентних пунктів перед одним діленням, без похибки додавання двох double на межі.
- Кожний фактичний удар має незалежний crit-roll. Обидва повтори використовують поточний `double_strike_power`: `ceil(D × q × (critical ? M : 1))`, без proc-рекурсії й повторного округлення. HP clamp після кожного; lethal первинний пригнічує proc, lethal другий пригнічує третій і його crit RNG. Completion/XP/платіж/NotifyChanged один раз/order, без carry. Hold lifecycle/guards — чинні U2b/U3.
- LastStrikeCount — фактичні 1–3 удари, LastHitDamage — їхня сумарна розрахована шкода до clamp, LastExtraStrikeDamage — сумарна шкода фактичних повторів; LastHitWasCritical — хоча б один крит. UI показує 2/3 фактичні рухи, фактичні d/t/q. Preview другого ступеня позначає його власний внесок, не повторює перші 20%.
- Каталог відтепер має explicit `FindForNode`: `.02` ціна/межа береться з окремого canonical node запису, попередні перші вузли — зі своїх чинних family записів. Quote, detail і tile використовують однаковий lookup; quote звіряє cap з registry. Досягнення/нагороди не підвищують purchased ranks.
- Schema 6 додає лише два нові canonical IDs з незалежними caps/prerequisites. Schema 1–5 не приймають їх навіть при rank 0. Load не переписує старі файли і не дарує нові ранги; наступний Save пише 6, зберігає точні wallet/XP/всі старі ранги та старі backups. Version >6 захищена; feedback/Hold не зберігаються.
- Double chance III, power II та triple II недоступні до власних slices. Наступний roadmap крок — U4, перший окремий auto slice; U3b не вмикає auto.

Локальні ризики: family ціна/cap помилково застосовані до tier II, перетин ймовірностей чи зайві RNG, третій удар після completion/подвійна нагорода, втрата старих рангів, обрізана статистика. Перевірки — node quote/cap + proc boundaries/crit/completion/Hold + schema 1–5→6; ізольовані кнопки/feedback/autosave/Continue та один rendered size. Build/широка регресія не потрібні.
