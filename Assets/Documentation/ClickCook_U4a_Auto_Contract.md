# U4a — базове періодичне автоготування

ADOPTED IMPLEMENTATION CONTRACT — 2026-10-24. Перший окремий slice U4: `node.auto_action_count.01` / «Вправний помічник I», prerequisite `node.click_strength.01:2`. Власні 10 рангів; ціна наступного N: `ceil(500 × 1.8^N)` у decimal з одним кінцевим округленням. Числа — початковий баланс ClickCook, не source rewards/доведений pacing.

- N=0: періодичне авто вимкнено. Базовий batch для майбутнього auto_action_chance має одну дію, але сам не запускає цикл. N≥1 вмикає періодичний цикл, `actions = 1 + N` (2–11), кожна дія по 1 HP, один цикл/с. auto_strength/frequency/multiplier/chance ще не продаються. Прев’ю першої покупки показує активацію та реальний batch, наступних — кількість дій.
- Авто діє лише під час cooking поточного активного order. Перший tick через повну 1 секунду unscaled time від першого активного кадру після вибору/відновлення. Немає негайного tick при виборі; не більше одного batch/кадр. Затриманий кадр дає один batch і новий дедлайн `now+1`, без catch-up/offline боргу.
- Кожна auto дія завдає 1 HP без криту, double/triple чи combat RNG; ручні modifiers не впливають. Дії обмежені поточним order, припиняються на HP=0. Completion/receipt/XP/payout/profile notification спільні з manual, рівно один раз/order. Надлишок batch не переходить на нове замовлення, наступне не обирається автоматично.
- Пауза (включно з pause/resume в одному кадрі), focus loss, system pause, controller disable, Back, result, end, зміна order скидають timer/binding. Після повернення до активного cooking починається новий повний інтервал, без паузового боргу. Hold та auto незалежні; у кадрі спершу обробляється Hold, потім auto, якщо страва ще активна.
- Прийнятий auto batch очищує manual feedback: LastActionWasAuto=true, LastAutoActionCount — фактичні дії, LastHitDamage — їхня шкода; LastStrikeCount=0, крит=false. Наступний manual trigger очищує auto feedback. HP-панель показує «Помічник», статистика — actions × strength і cycles/с. Для шести рядків статистики використано шрифт 20 замість 23 у тому самому панелі.
- Купівля через чинні node quotes лише між днями, з cap/prerequisites/owner/replay/pause/funds guards та автозбереженням. Schema 7 додає тільки canonical auto_action_count.01 (0–10); schema 1–6 відхиляють ID навіть при rank 0. Старі wallet/XP/ранги/backup читаються без eager rewrite чи безкоштовного авто; Save пише 7, >7 захищено. Timer/binding/day/feedback не зберігаються.
- Наступний slice U4b — перший auto_action_chance (one-roll-on-first-cooking/order, без повторного roll на Back за manifest); далі окремі strength/multiplier/frequency slices. U4a не оголошує всю авто-гілку завершеною.

Локальні ризики: зайвий/накопичений tick, manual RNG у авто, подвійна нагорода при спільному completion, удар після переходу стану, втрата старих ranks/schema, обрізана статистика. Потрібні scoped model/storage та ізольований live tick/pause/completion/autosave/Continue; попередні manual proc checks для спільного completion boundary. Player build і широка регресія не потрібні.
