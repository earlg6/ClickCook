Статус: ADOPTED DESIGN, 2026-10-23. Це контракт контенту для U1, не ввімкнені gameplay effects.

**92 плитки: 76 окремих референсних записів і 16 явно позначених доповнень ClickCook.** 38 effect families плюс безкоштовний root. Усі 25 popup, які лишалися в черзі, прочитані через Chrome Computer Use. Огляд має 76 видимих плиток; звірка оперує конкретними popup-ідентичностями, а не вважає число вибраних Figma objects кількістю upgrades. Це завершений кухонний план за наданими матеріалами; повнота всіх версій оригінальної FishSim не заявляється.

Джерельні назви/ранги/числа залишено для provenance у колонці спостережень. Заголовок 7:1445 обрізаний у самому source image; його III ступінь і ефект читаються. Невідомий заголовок не вигадується. Оператори preview FishSim не виводяться з округлених цифр. Нові назви й усі описи призначені для ClickCook.

Залежності нижче — **прийнятий граф ClickCook**, адаптований до кухонних систем, а не твердження про точне копіювання всіх ребер FishSim. `:1`, `:2`, `:3` — придбаний ранг конкретного вузла, `:max` — придбані всі ранги попереднього ступеня. Усі умови AND. Source grants не задовольняють purchased prerequisites. Неактивні гілки не блокують працюючий Click Strength.

На U1 можна купити лише node.click_strength.01: він зберігає чинні 0–15 рангів/ціну/силу 6A. node.kitchen_license.01 безкоштовний, віртуально відкритий; не створює нагороду/запис у schema-1. Решта вузлів показує «Ефект ще не реалізовано» й не проводить покупку. Нові ранги окремих вузлів, maxRank, ціни й міграція проходять контракт відповідного effect slice перед продажем; source maxRank не є нашим cap автоматично. Жоден майбутній вузол не повторно застосовує legacy rank.

## Контракт адаптованих механік

- Manual/hold: крит — окремий roll фактичного удару; double/triple обирають один результат із максимумом трьох ударів по поточній страві, без рекурсивного proc або другої виплати. Auto не критує. Додаткові удари зупиняються після completion. Сила додаткового удару належить double_strike_power; triple використовує той самий параметр, якщо slice не визначить інше явно.
- Auto: auto_action_count визначає цілу кількість дій у tick, auto_strength — роботу кожної, auto_frequency — ticks/с, auto_strength_multiplier — множник сили. Базовий batch має одну дію силою 1; періодичні ticks починаються лише після ввімкнення auto у відповідному slice. Дії обмежені поточним order, без перенесення зайвих дій на наступний. Меню/пауза/result не накопичують борг tick. auto_action_chance адаптує auto-hook: один roll на першому вході в cooking конкретного order може дати один негайний звичайний auto batch навіть без періодичного auto. Back не повторює roll, автоматичного вибору order немає. Шанс, кількість, сила і частота зберігаються окремо.
- preparation_efficiency зменшує початкову роботу страви для manual і auto: `work = max(1, ceil(baseWork × (1 − reduction)))`. Reduction обмежено 0.80. Snapshot один раз/order; Back відновлює той самий початковий snapshot, не перемножує знижку повторно. Стартовий прогрес накладається після цього, не завершує order самостійно. Це ADOPTED формула ClickCook, не виведена зі source current/next.
- Швидкий вибір: normal window дає грошовий бонус, precision window (не довше normal) — початковий прогрес; повільний вибір без штрафу. Grant один/order. Критичні секунди мають cap і переходять лише після завершення order на наступне нове відвідування дошки; Back скидає pending, завершення дня/меню/restart очищує банк. Точні секунди/cap/rank перед відповідним slice.
- Диспетчер: I підсвічує найкращий поточний order за очікуваними у.е./роботу; II додає перемикач «дохід / Dish XP за роботу»; III показує обидва рейтинги й позначає перетин. Оцінка використовує вже показані гарантовані нагороди/роботу, без пророкування RNG. Pulse — оновлення підсвічування/рейтингу. Базовий інтервал 3 с, зниження від frequency обмежене мінімумом 0.5 с; перше обчислення одразу при вході на дошку. Точні прирости/ранги — перед продажем. До появи базового tracker ефект frequency недоступний. Це наш аналог sonar; неоднозначний source Expert preview не видається за готову поведінку.
- location_value використовує authored рівень поточної LocationData, без прихованої залежності від Restaurant XP. day_income_bonus нараховує один додатковий бонус від суми базових продажів завершеного дня; база виключає цей бонус, passive, попередній wallet і перезапущений незавершений день. Receipt один раз; rounding/ставки — перед 8A/U5.
- Flat contributions додаються; multiplier-вузол дає окремий factor, фактори перемножуються. Chances додаються в процентних пунктах і обмежуються допустимою ймовірністю; залежний double/triple roll потребує спільного розподілу перед U3b. Rarity flat і multiplier впливають на узгоджені ваги якості з нормалізацією у U6; rare шанс зі screenshot не роздається всім п’ятьом якостям. Невідомий числовий preview не показується як працюючий бонус.
